# レイアウトシステム

## 1. ブレークポイント(MUIデフォルトを使用)

| 名前 | 幅 | 想定デバイス |
|------|----|-------------|
| xs | 0〜 | スマホ(縦) — **共有ページの基準** |
| sm | 600〜 | スマホ(横)・小型タブレット |
| md | 900〜 | タブレット・小型PC — **運営画面のサイドバー出現点** |
| lg | 1200〜 | PC — コンテナ最大幅 |

- デザインは xs(375px)から組み立てる(モバイルファースト)
- `useMediaQuery(theme.breakpoints.up('md'))` で分岐。生のpx値でのメディアクエリ禁止

---

## 2. ページ構造

### 運営者画面(AppLayout / TournamentLayout)

```
┌──────────────────────────────┐
│ AppBar(ロゴ / 大会名 / ユーザーメニュー)      │
├────────┬─────────────────────┤
│ Sidebar │  コンテンツ(max-width: 1200px)     │
│ (md以上) │  padding: 24px                    │
│         │                                   │
└────────┴─────────────────────┘
  md未満: Sidebarの代わりに下部固定タブ(BottomNavigation)
```

- サイドバー項目: 概要 / 参加者 / ラウンド / 順位 / 設定
- コンテンツは `Container maxWidth="lg"`

### 共有ページ(SharedLayout・スマホ優先)

```
┌──────────────────┐
│ ヘッダー(大会名 + 第Nラウンド) │ ← sticky
│ タブ(組み合わせ / 順位表)     │ ← sticky
├──────────────────┤
│ コンテンツ(max-width: 600px  │
│  中央寄せ、padding: 16px)     │
└──────────────────┘
```

- ナビゲーション要素は最小限(参加者は「見る・入力する」だけ)

---

## 3. グリッドと配置

- 一覧のカード配置: `Grid` で xs=12 / sm=6 / md=4
- フォーム: 1カラム縦積み(max-width: 600px)。2カラムフォーム禁止(入力順が迷子になる)
- 表(順位表・参加者一覧): 横スクロールを許容する場合は表自体を `overflow-x: auto` のコンテナで包む(ページ全体を横スクロールさせない)

---

## 4. 余白ルール

| 場所 | 値 |
|------|----|
| ページ上下 | 24px(スマホ16px) |
| セクション間 | 32px |
| カード内 | 16px |
| フォーム項目間 | 16px |
| 固定フッター(結果入力の送信ボタン等)の高さ | 72px + safe-area-inset-bottom |

- スマホの主要アクション(結果送信)は**画面下部固定**(親指が届く位置)

## 5. 印刷レイアウト(A4)

帳票印刷(S13)専用のレイアウトルール。ブラウザ印刷(Chrome/Edge限定)を前提とする。

### 5-1. 上記ルールとの関係(例外規定)

- **`@page`・mm/pt単位は §1 ブレークポイント規約の対象外**。ブレークポイントは画面幅(px)に対する規約であり、
  紙の物理サイズ(A4=210×297mm)とは無関係。値は `theme.print` トークン(`01_design_principles.md`)に集約し、
  コンポーネント内でのハードコードは禁止する(この点は他のトークンと同じ)
- **`@media print` は「生のpx値でのメディアクエリ禁止」(§1)の対象外**。これはメディア"タイプ"の指定であり、
  ブレークポイントの代替ではないため

### 5-2. ルート構成

`@page`はドキュメント単位でしか向き(portrait/landscape)を切り替えられないため、**帳票ごとに専用ルート**
(`/tournaments/:id/print/{roster,cross-table,match-cards}`)を持つ専用レイアウト(`PrintLayout`)を使う。
`AppLayout`/`TournamentLayout`の外に置き、AppBar・サイドバー・下部タブを一切継承しない。

```
┌──────────────────────────────┐
│ 戻るボタン / 印刷ボタン(画面のみ・印刷時は非表示) │
├──────────────────────────────┤
│ PrintReportHeader(大会名・帳票名・開催日)      │
│ 帳票本体(A4 縦 or 横)                        │
└──────────────────────────────┘
```

### 5-3. 帳票ごとの向き・面付け

| 帳票 | 向き | 面付け |
|---|---|---|
| 参加者名簿 | 縦(portrait) | 1ページに表を流し込む(ページ数は参加者数に応じて可変) |
| 戦績一覧表 | 横(landscape) | グループごとに改ページ。単一グループ大会はグループ見出しを省略 |
| 対局カード | 縦(portrait) | 個人戦は4列×4行(16面、A8相当)。totalRounds≥7は4列×3行(12面)に落とす。団体戦は2列×4行(8面、A7相当。ボード列が入るため個人戦より広い面が必要) |

### 5-4. 改ページ・繰り返しヘッダー

- 改ページは `breakAfter: 'page'`(グループ境界・対局カードのページ境界)、行の分断防止は `breakInside: 'avoid'`
- 表のヘッダー行は `thead { display: 'table-header-group' }` で各ページに繰り返す
- 罫線・ヘッダー地色を確実に印刷するため `print-color-adjust: exact` を設定する(Chrome/Edgeの既定は背景非印刷)
