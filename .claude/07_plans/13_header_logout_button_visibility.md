# 13. ヘッダーのログアウトボタンの視認性を改善する

- Status: done
- Issue: #183
- PR: -

---

## 1. 背景・目的

運営者画面共通レイアウト(`AppLayout`)のヘッダー右端にあるログアウトボタンは、
`color="inherit"` のみが指定された `variant="text"` の `Button` で、塗り背景を持たない。
ヘッダー背景がテーマの `primary.main`(`#1B5E43`・深緑)であるのに対し、ボタンの文字・アイコンも
`inherit` で同系色(白文字)になるため、ボタンの輪郭がヘッダーに溶け込み「押せる要素」だと
気づきにくい(Issue #183)。

本計画は、ログアウトボタン単体に既存のデザイントークン(`primary.light`/`primary.dark`)で
背景色・文字色を与え、ヘッダー背景との間にコントラストを作ることで解決する。新しい色トークンは
追加しない。**フロントエンドのテーマ変更ではなく、`AppLayout.tsx` 内のログアウトボタン1箇所への
`sx` 指定のみ**で対応し、他画面・他ボタンには影響しない(Issue #183の制約どおり)。

**最重要原則: 正確性 > シンプルさ > コスト > 機能 > 速度**

## 2. 画面シナリオ

- 運営者が 運営者画面(大会一覧・大会詳細等、`AppLayout` 配下のどの画面)を開くと ヘッダー右端の
  ログアウトボタンが背景色付き・角丸のボタンとして視認でき、ヘッダーの地色から明確に区別できる
- 運営者が ログアウトボタンにマウスカーソルを乗せる/キーボードでフォーカスすると 押せる要素で
  あることが分かる視覚的なフィードバックが起きる(色の濃淡変化)
- 運営者が ログアウト処理中(`logoutMutation.isPending`)にボタンを見ると 既存どおり無効化された
  見た目になり、連打による二重リクエストを防げる(挙動は変更しない)
- 参加者は本変更の影響を受けない(`AppLayout` は運営者専用レイアウトで、共有ページ
  (`SharedResultPage` 等)は別レイアウトのため対象外)

観点の抜けチェック:

- 運営者(PC)のみが対象。参加者(スマホ・共有ページ)には影響しない
- 個人戦・団体戦で `AppLayout` は共通のため、両方に同じ見た目が適用される(挙動差なし)
- グループ分けあり/なしで変わらない(ヘッダーはグループ機能と無関係)
- 競合・権限外アクセス: 該当なし(表示のみの変更で、ログアウトAPI呼び出しのロジックには触れない)

## 3. UI仕様

新規画面ではなく既存ヘッダー内のボタン1個への配色変更のため、`00_basic_design.md` §4 の優先度
(4. 運営者管理画面はMUI標準に寄せてよい)に従い、レイアウト構成全体の記述は省略し、対象ボタンの
配色のみを記述する。新規画面・大きなレイアウト変更のいずれにも該当しないため、`.stories.tsx` は
作成しない(`04_development_process.md` §5.1の対象外)。

### ログアウトボタン(AppLayout)

- **変更前**: `variant="text"`(デフォルト)・`color="inherit"` のみ。背景は透明、文字・アイコンは
  白(ヘッダーの `contrastText`)
- **変更後**:
  - 背景色: `primary.light`(`#E8F2ED`。既存トークン。現在は「選択状態の背景」「共有ページの
    ヘッダー帯背景」に使用中で、新規追加ではなく流用)
  - 文字・アイコン色: `primary.dark`(`#0F3D2A`。既存トークン。現在は「ホバー・アクティブ」用途)
  - 角丸: 追加指定は不要。`theme.shape.borderRadius`(8px)は既に `MuiButton` の root に適用
    済みで、背景が透明だったため見えていなかっただけ(`theme/index.ts` に個別の radius 追加は不要)
  - コントラスト比(WCAG AA基準4.5:1に対して算出): 文字色`primary.dark`と背景色`primary.light`の
    組み合わせで **約10.7:1**。ヘッダー背景`primary.main`とボタン背景`primary.light`の
    組み合わせでも**約6.7:1**の差があり、ボタンの輪郭がヘッダーの地色から明確に分離される
- **4状態相当(データ取得を伴わないため簡略)**:

  | 状態 | 表示 |
  |---|---|
  | 通常 | 背景`primary.light`・文字/アイコン`primary.dark`・角丸8px |
  | ホバー/フォーカス | 通常より僅かに濃い塗りで押せることを示す(新規トークンは追加せず、既存のホバー時の濃淡表現の範囲で調整。正確な値は実装時にローカル実機で確認する) |
  | 無効(ログアウト処理中) | 既存どおり `disabled` の薄色表示。挙動は変更しない |
  | エラー(ログアウト失敗) | 既存どおり `useSnackbar` のエラートーストで通知。ボタン自体の見た目は変更しない |

- **大量データ時**: 影響なし(ヘッダーは全画面共通で件数に依存しない)
- **レスポンシブ**: 影響なし。375px・デスクトップともに同じ配色・形状(ユーザー名の表示/非表示切り替えなど既存のレスポンシブ挙動は変更しない)
- **既存画面との一貫性**: `primary.light`/`primary.dark` はいずれも既存の設計原則
  (`01_design_principles.md`)に定義済みのトークンをそのまま用途追加するだけで、新しい配色パターンを
  持ち込まない
- **新しいUIパターンの有無**: 無し。既存トークンの組み合わせのみで、`02_component_design.md` への
  新規パターン追加は不要

## 4. 技術設計

- **レイヤーごとの変更点**: フロントエンドのみ、かつ `AppLayout.tsx` 内のログアウトボタン1箇所。
  domain/application/presentation(バックエンド)への変更は無い
- **API変更**: 無し。`schema/openapi.yaml` の更新も無い
- **データモデル**: 変更無し
- **フロントエンド**:
  - `frontend/src/components/layouts/AppLayout.tsx` のログアウト `Button`(51-58行目)に
    `sx` で `backgroundColor: 'primary.light'`・`color: 'primary.dark'` を指定する
    (`color="inherit"` プロパティは撤去し、`sx` の `color` に置き換える)
  - `theme/index.ts` の `MuiButton.styleOverrides`(グローバル設定)は変更しない
    (Issue #183 の制約どおり、他画面の全ボタンに影響させない)
  - 他ファイルへの変更は不要(調査済み。ヘッダーの構成要素はロゴ・ユーザー名・ログアウトボタンの
    3つのみで、同種の塗りボタンは他に存在しない)
- **マッチング・順位計算**: 触れない
