## 2. 画面遷移図

### 運営者フロー

```
S01 トップ
 └─▶ S02 ログイン ─(Google OAuth2)─▶ S03 大会一覧
                                        ├─▶ S04 大会作成 ──▶ S05 大会管理
                                        └─▶ S05 大会管理
                                             ├─▶ S06 参加者管理(CSVインポート含む)
                                             ├─▶ S07 ラウンド管理
                                             │     ├─ 組み合わせ生成
                                             │     ├─ 結果入力
                                             │     └─ ラウンド確定 ─▶ 次ラウンドへ
                                             ├─▶ S08 順位表
                                             └─▶ S09 大会設定(公開範囲・共有URL・削除)
```

### 参加者フロー(共有URL経由・ログイン不要)

```
共有URL(QR/リンク) ─▶ S10 共有ページ
                        ├─ 組み合わせ確認(自分の卓番号・対戦相手)
                        ├─▶ S11 結果自己申告(大会設定で許可時のみ。両者の申告が一致すると自動確定)
                        ├─ 順位表確認
                        └─ 対戦結果確認(全ラウンドの対戦相手・結果を一覧)
```

## 3. 大会運営の状態と画面の関係

| 大会状態 | S06 参加者管理 | S07 ラウンド管理 | S10 共有ページ |
|---------|--------------|----------------|--------------|
| PREPARING | 追加・編集・削除可 | ラウンド生成不可 | 「開始前」表示 |
| IN_PROGRESS | 棄権処理のみ可 | 生成・入力・確定可 | 組み合わせ・順位表示 |
| FINISHED | 閲覧のみ | 閲覧のみ | 最終結果表示 |

## 4. ナビゲーション設計

- **運営者画面**: 左サイドバー(PC) / 下部タブ(スマホ)。項目: 概要・参加者・ラウンド・順位・対戦結果・設定
  (順位と対戦結果は内容の重複を避けるため別メニュー。順位=順位カード(RankingBoard)、対戦結果=対局グリッド(MatchResultsTable))
- **共有ページ**: タブ切り替え(組み合わせ / 順位表 / 対戦結果)。ヘッダーに大会名と現在ラウンドを常時表示
- 大会管理系画面(S05〜S09)は共通レイアウト(`TournamentLayout`)でラップし、大会名・状態バッジを常時表示する
- **S13帳票印刷への導線**: 大会概要(S05)の「帳票印刷」カードから入る。サイドバー・下部タブには項目を追加しない
  (下部タブは6項目で横スクロールなしに収める設計のため、7項目目を足すとレイアウトが崩れる)。
  参加者管理(S06)・対戦結果(S05配下)にも文脈に応じた印刷ボタンを置く

---

## 5. 団体戦の画面の扱い

- 団体戦は画面(S01〜S12)を新設せず、各画面が `tournament.competitionType` で表示を分岐する
  - S04大会作成: 競技形式(個人戦/団体戦)・チーム制(3/5)の選択項目を追加
  - S06参加者管理: 団体戦では「チーム管理」(チーム名・メンバー登録・役割割当・CSVインポート)に置き換わる
  - S07ラウンド管理・S08順位表・対戦結果(S05配下)・S10共有ページ: 団体戦ではチーム名のみを表示し、対局結果はボード(主将戦・副将戦…)単位の内訳を併記する。メンバーの個人名は一切表示しない
  - S11結果自己申告: 団体戦では専用ルート `/s/:token/team-matches/:mid` を使い、「どちらのチームか」選択 → 全ボード分の結果をまとめて入力 → 確認 → 送信、の1画面フローになる(ステップ数は個人戦と同じ3段階)
- 詳細は `05_swiss_pairing_algorithm.md` §5 を参照

## 5-2. S13帳票印刷の個人名の線引き

S07/S08/対戦結果/S10に適用される「団体戦はメンバーの個人名を一切表示しない」制約(§5)は、**対局結果を見せる画面**に対するもの。
S13の各帳票は配布先(参加者向けか運営専用か)で線引きが変わるため、帳票ごとに以下のとおり明確化する。

| 帳票 | 配布先 | 個人戦 | 団体戦 |
|---|---|---|---|
| 対局カード | 参加者/チームに配布 | 氏名・所属・段級位・No. | チーム名 + ボード役割(主将・副将…)のみ。個人名なし |
| 対戦結果表 | 掲示・配布 | No.・名前・段級位 | No.・チーム名。個人名なし |
| 参加者名簿 | **運営専用** | 氏名・所属・段級位 | メンバー氏名・段級位・役割を印字してよい(受付照合用) |

団体戦の参加者名簿は運営専用であることをフッターに明記し(「運営用(掲示・配布しないでください)」)、参加者に配布・掲示しない。

**対戦結果表は大会開始前に印刷する手書き記入用シート**である(対局カードと同じ運用)。No.・名前(・段級位)以外の
対戦相手・結果・勝点・SOS・SOSOS・順位はラウンドの進行に合わせて手書きで記入するため、印刷時点では常に空欄で出す。
ラウンド列も生成済みラウンド数によらず `totalRounds` 分を最初からすべて出す。

## 6. UX上の重要ルール

1. **結果入力は「自分はどちらか」選択 + 「勝ち/負け」選択 + 確認の3ステップ**: 対戦相手と結果を偽って一方的に確定できないよう、
   両者がそれぞれ自分の結果を申告する(片方の申告だけでは確定しない。一致すると自動確定)
2. **破壊的操作は必ず確認**: ラウンド確定・大会削除・トークン再発行はダイアログで確認。大会削除は大会名の入力を要求
3. **ラウンド確定のブロックは「結果が未確定」の対局全て**: 結果(result)がNONEのまま残る対局が1件でもあると確定できない。
   片方のみ申告・申告が一致しない対局もresultはNONEのままなので同様にブロックされ、警告表示とともに運営者が
   結果を直接確定するまで確定できない(詳細は結果確定の運用ルールとして`13_security_design.md`参照)
4. **オフライン考慮**: 結果送信失敗時はリトライ可能なエラー表示(会場の電波状況が悪いケースを想定)
5. **URLで状態復元可能**: すべての画面はURL直アクセスで再現できること(SPAでもディープリンクを壊さない)
